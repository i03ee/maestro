# بنية النواة

## الشكل

```text
        مهمة جديدة (فكرة أو طلب)
                 │
                 ▼
        ┌──────────────────┐
        │  عقد IR (AppIR)  │  ← القواعد IR-01..IR-14
        └────────┬─────────┘
                 │  (مرفوض ⇐ مُبلَّغ بالقاعدة المكسورة)
                 ▼
        ┌──────────────────┐
        │ حارس الصلاحيات  │  ← قدرة مصرّح بها؟ صلاحية ≤ السقف؟ موافقة بشرية؟
        └────────┬─────────┘
                 ▼
        ┌──────────────────┐
        │  حارس الميزانية  │  ← سقف صلب: تكلفة + رموز
        └────────┬─────────┘
                 ▼
        ┌──────────────────┐
        │   الموجّه        │  ← محلي ← واجهة ← احتياطي (ترتيب ثابت)
        └────────┬─────────┘
                 ▼
        ┌──────────────────┐
        │   سجل الأدلة     │  ← JSONL إلحاقي بسلسلة بصمات
        └──────────────────┘
```

## المكوّنات

### `maestro.ir` — عقد المهمة

مستند JSON يصف ما يجب إنجازه: القدرة، النيّة، مستوى الصلاحية، الخطوات
(وكيل + أدوات + ميزانية)، ميزانية المهمة، التكرار والدليل إن كانت القدرة
حرجة. لا يبدأ تنفيذ أي مهمة قبل اجتياز القواعد الأربع عشرة.

| القاعدة | الموضوع |
|---|---|
| IR-01 | إصدار IR مدعوم |
| IR-02 | تسمية القدرة بمعرّف متدرّج |
| IR-03 | نيّة واضحة ومحدودة |
| IR-04 | مستوى صلاحية ضمن 1..3، والصلاحية 3 تتطلب موافقة بشرية |
| IR-05 | عدد الخطوات ضمن الحد |
| IR-06 | معرّفات خطوات فريدة |
| IR-07 | كل خطوة تعلن وكيلاً |
| IR-08 | الأدوات ضمن القائمة المسموحة |
| IR-09 | ميزانية موجبة وداخل السقف العام |
| IR-10 | ميزانية الخطوة داخل ميزانية المهمة |
| IR-11 | مهلة زمنية محدودة للقدرات الحرجة |
| IR-12 | تكرار نماذج للقدرات الحرجة (عدد لا نسبة) |
| IR-13 | أدلة إلزامية للقدرات الحرجة |
| IR-14 | لا أسرار في المدخلات |

### `maestro.routing` — الموجّه

سلسلة واحدة لكل قدرة، مبنية على `RoutingPolicy` (ترتيب ثابت للطبقات +
تجاوزات لكل قدرة). الفشل يُسجَّل كـ`Attempt` ويُسقَط إلى الطبقة التالية.
**ميزانية المهمة قرار تشغيلي**: تجاوز السقف يوقف المسار ولا يُسقَط.

الأنماط التي يتعامل معها الموجّه كلّها تتبع واجهة `Provider` واحدة، فيعمل
المزوّد المحلي والمزوّد البعيد بنفس الاختبار.

### `maestro.guards` — الحرّاس

- `BudgetGuard`: سقف تكلفة وسقف رموز. `authorize` قبل الطلب، `consume` بعده.
- `PermissionGuard`: قائمة قدرات مصرّح بها + سقف صلاحية + موافقة بشرية مسجّلة
  للصلاحية 3. الرفض نهائي ولا يوجد مسار «تخطّي».

### `maestro.evidence` — سجل الأدلة

سجل JSONL إلحاقي. كل سطر يحمل بصمة `sha256` مشتقّة من بصمة السطر السابق
ومحتوى السطر الحالي. `verify()` يعيد حساب السلسلة كاملة: صحيح أو خطأ.

### `maestro.baseline` — الخط الأساسي

يسجّل لكل مخرج: الزمن البشري، التكلفة، هل قُبل دون تحرير، وهل تكرّر الطلب
خلال أسبوعين. الأرقام **وصف** لا بوابة — انظر `docs/PROTOCOL.md`.

### `maestro.provenance` — سجل التبعيات

كل تبعيات يجب أن تكون مسجّلة في `docs/provenance/dependencies.json` بقرار
(allow/deny) ورخصة وتبرير. التبعية غير المسجّلة تُرفض عند البوابة.

## حدود ما هو مبنيّ اليوم

- النواة (العقود، الموجّه، الحرّاس، السجل، الخط الأساسي، السجل) **تعمل الآن**.
- طبقة الوكلاء الحيّة (PydanticAI + DBOS) **ليست مفعّلة**: تحتاج مفتاح مزوّد.
- الاختبارات كلّها تعمل بلا شبكة وبمزوّد اختباري حتمي.
