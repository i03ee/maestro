# ADR 0007: تنفيذ متين بسجل خطّي، بلا قاعدة بيانات

- **الحالة:** مقبول
- **التاريخ:** 2026-11-18

## السياق

الوكلاء يموتون: انقطاع شبكة، إعادة تشغيل، انتهاء مهلة. المهمة التي بدأت ولم
تنتهِ تكون ضائعة أو — أسوأ — منفّذة مرّتين فتُنفَق التكلفة مرّتين.

## القرار

1. سجل متانة JSONL إلحاقي: كل مهمة تكتب «بدأت» قبل التنفيذ و«انتهت» أو
   «فشلت» بعده. لا قاعدة بيانات، لا خدمة خارجية، لا تكلفة.
2. **مفتاح تكرارية**: الطلب بالمفتاح نفسه بعد الإنجاز يعيد النتيجة المخزّنة
   ولا يستدعي النموذج ولا يُنفق.
3. **الاستئناف**: أي مهمة سطرها «بدأت» بلا سطر نهاية تُستأنف من السجل؛
   مستند المهمة محفوظ في السجل نفسه، فلا حاجة لحالة خارجية.
4. الرفض (فشل بوابة) يُسجَّل حدث «failed» — **لا** إنجاز. المهمة القابلة
   للإصلاح تُعاد بمفتاح جديد أو بعد تصحيح المستند.

## الآثار

- **إيجاب:** لا تنفيذ مزدوج، ولا مهمة ضائعة بعد الموت، وكل ذلك بلا تبعيات.
- **سلب:** السجل ينمو ولا يُقصّ؛ يحتاج تدويراً (rotation) لاحقاً. وكتابة
  السجل نفسها عملية I/O تُضاف إلى زمن المهمة.
