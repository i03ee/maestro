# MAESTRO

**شركة مصغّرة من الوكلاء** — تبني منتجاتها بنفسها: تفهم المطلوب، تخطّط، تنفّذ،
تراجع نفسها، وتسجّل دليلها.

هذا المستودع هو **نواة الشركة**، وليس المنتج. أول تطبيق تنتجه الشركة هو مشروع
**نَسمة** (Nasma) — منصة تجارة جمال عراقية بواجهة ويب عربية RTL وتطبيق Expo —
وهو مستودع منفصل، ويستخدم هذه النواة.

> **الحالة: الموجة صفر.** البنية، والعقود، والحرّاس، وسجل الأدلة، وبوابات الجودة
> مبنية وتعمل. طبقة الوكلاء الحيّة (PydanticAI) لم تُفعَّل بعد: تحتاج مفتاح
> مزوّد، وكل ما عداها جاهز ويعمل بلا تكلفة.

## ما الذي في هذا المستودع

| المسار | الدور |
|---|---|
| `src/maestro/ir/` | تمثيل التطبيق (AppIR): عقد كل مهمة + 14 قاعدة تحقق (`IR-01`..`IR-14`) |
| `src/maestro/integrations/nasma/` | مسار «بيانات المنتج»: من ملف مورّد إلى بطاقة بثلاث لغات — منتج واحد = مهمة واحدة |
| `src/maestro/runtime/` | مُشغّل القدرة: عقد IR ← سجل القدرات ← الصلاحيات ← الميزانية ← التوجيه ← الدليل |
| `src/maestro/routing/` | موجّه النماذج: طبقة محلية، ثم واجهة، ثم احتياطي، بإسقاط منظّم ومسجَّل |
| `src/maestro/guards/` | حارس الميزانية (سقف صلب) وحارس الصلاحيات (قدرة مصرّح بها + موافقة بشرية للصلاحية 3) |
| `src/maestro/durable/` | تنفيذ متين: سجل يستأنف بعد الموت، ومفتاح تكرارية يمنع التنفيذ المزدوج |
| `src/maestro/evidence/` | سجل أدلة إلحاقي بسلسلة بصمات — أي تعديل لاحق يُكشف |
| `src/maestro/baseline/` | مسجّل الخط الأساسي: زمن بشري وتكلفة لكل مخرج قبل التحسين |
| `src/maestro/provenance/` | سجل التبعيات: كل حزمة لها قرار ورخصة وتبرير |
| `scripts/` | بوابتان تعملان محلياً بلا شبكة: ثوابت المستودع، وبوابة التراخيص |
| `docs/` | القرارات (ADR)، البروتوكول، سجل المصادر، وبنود الحصاد |

## التشغيل

```bash
# الفحوص كلها تعمل بلا شبكة وبلا تثبيت
python3 scripts/validate_repo.py
python3 scripts/check_licenses.py
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

لا تبعيات وقت تشغيل في النواة: كل شيء من المكتبة القياسية. هذا مقصود —
«المجاني» هنا يعني **صفر تكلفة إلزامية**، لا صفر تكلفة إجمالية.

## القواعد التي لا تُكسر

1. **نقبل الكود، نرفض الترخيص.** كل سطر مستعار يحمل مصدره ورخصته وسجل اختبار العقد.
2. **البوابة قبل الوعد.** لا يُدمج شيء قبل أن يمرّ اختبار عقد.
3. **بلا نسب خطأ.** كل فحص ثنائي: يجتاز أو يفشل. لا «نسبة نجاح مقبولة»، ولا
   «أخطاء مسموحة». التفاصيل في [`docs/PROTOCOL.md`](docs/PROTOCOL.md).
4. **خطوة صغيرة، وكيل واحد، جزء واحد.** كل طلب دمج يفعل جزءاً واحداً ويمرّ على
   كل البوابات.
5. **القياس قبل التفاؤل.** كل قدرة لها خط أساس رقمي قبل أن يُقاس تحسّنها.
